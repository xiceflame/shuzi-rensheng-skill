## 2. 交付范围

功能目标：本机自检与标准错误事件、安装编号、可预览的一键诊断包、明确授权的轻量上传、服务端持久化接收、安装状态与故障分组后台、恢复验证。

本地模式为默认值。安装、导入技能、读取文档不能隐式启用上报。新诊断能力不依赖 LLM，不能通过上传微信数据库、聊天、模型输入输出、密钥或原始日志全集排障。

### A. 安装身份与版本

每一处安装生成随机安装编号，保存在知识库外的应用状态目录。部署组由用户主动绑定；进程运行编号与持久安装编号分开。不得从微信号、手机号、硬件标识或用户名派生安装编号，也不得把可关联编号宣传为完全匿名。

版本信息区分安装包版本、实际运行组件版本、部署副本与当前包是否一致。构建指纹仅对明确列入清单的代码文件计算，不读取用户资料计算指纹。定时任务指向旧副本时标注版本偏差，不擅自改写旧任务。

### B. 本机诊断

诊断聚合现有任务 JSON 回执、恢复覆盖报告、导出报告与索引状态。仅解析所需技术字段，不读取原始日志正文、聊天或附件。

检查项包括依赖、配置是否可解析、目标目录是否存在及可访问、磁盘余量、已配置调度与实际入口、任务超时、索引积压、恢复和导出失败。缺少检查依据时返回 unknown，而不是通过。没有任务计划、没有新资料时，不因为长期未产出而自动判定故障。

每个检查结果提供固定错误码和预定义的中文处理说明；不向事件加入异常对象的任意字符串。任务检查必须区分进程退出、产物存在和业务已验收。系统日期不准、休眠、断网可能影响状态判断，应保留 unknown/stale 表述。

本机报告可在终端和独立本地 HTML 中查看；Obsidian 只展示用户批准的简化状态页，不把详细环境报告或诊断包加入知识库索引。

### C. 用户可控反馈

三种模式：仅本地；明确启用的自动技术反馈；用户预览并确认的单次诊断发送。

注册接收服务需要用户明确指定可信 HTTPS 地址。公开代码包不内置全体用户共用的管理凭据或维护者机器人 webhook。每个安装的提交凭据只允许提交与读取自身回执；管理权限分开，并提供撤销方式。

关闭自动反馈后不再发起新的自动请求，并处理未发队列。已经发出的网络请求无法承诺撤回，服务端已保存记录的删除与客户端停发是两个不同操作。更换服务端地址必须重新授权；禁止自动跟随可能携带凭据的重定向。

### D. 诊断事件与诊断包

白名单字段包括安装编号、事件和任务编号、组件、有限版本信息、错误码、阶段、耗时区间、必要数量区间和固定检查项。客户端和服务端均校验字段和大小；未知字段、任意自由文本、完整路径和原始异常信息不接收。

诊断包只能包含同一白名单的数据及人类可读说明。发送前展示具体内容与文件指纹，确认绑定到这一次具体报告，不能批准一个文件后上传另一份数据。不自动打包 SQLite、密钥清单、内存转储、完整配置、聊天和原始日志。

深度诊断初版仍受相同内容边界约束；需要真实资料才能定位的问题，由用户在独立、明确授权的支持流程处理，不能偷偷扩展自动反馈字段。

### E. 发送队列与状态报到

结构化事件先落本地有界队列，再由独立任务处理。队列设置事件数、体积、保留期与重试上限，记录丢弃计数。采用持久化重试、退避、随机抖动和事件编号去重；服务端确认已持久化后再标记送达。

错误按组件和固定错误码聚合，避免同一故障刷屏；恢复时产生对应恢复事件。状态报到只对启用反馈的安装执行。后台超过预期周期未收到消息时标记“暂未收到状态”，不能断言机器损坏。

上报模块异常不能改变原业务任务的成功或失败退出码；也不能因为发送失败而终止采集或修改资料。主任务中的诊断钩子不直接等待远端网络。

### F. 接收服务与维护后台

提供轻量接收服务，要求持久化回执、幂等、严格字段校验、请求大小限制、安装级限流和凭据撤销。客户端无法枚举其他安装或读取其报告。注册入口采用受控邀请，不把未知安装默认纳入可信后台。

维护后台至少提供安装列表、版本分布、最近成功阶段、当前故障、最近收到状态时间、同类问题影响范围及恢复记录。按服务器收到时间和客户端发生时间分别展示，防止客户端时钟错误覆盖较新的状态。

后台仅向维护者认证开放；所有用户可控字段转义显示。IP、完整 URL、认证头等不进入默认访问日志。部署时需要 TLS 和受控反向代理；标准库开发服务器不作为公网生产服务器。

飞书提醒作为服务端可选项，仅发安装编号、错误类别和后台入口，不发送诊断原文或用户资料。通知失败保留待处理状态，不能以函数调用完成代替发送成功。

## 3. 与现有链路的接线点

| 现有位置 | 新功能需要接入的结果 |
|---|---|
| `install.sh` 与 `setup/SETUP.md` | 本地自检入口、明确反馈模式选择，不自动开通 |
| `engine/run.py` | 任务开始、结束、超时和固定错误码；日志正文不上传 |
| `collector/wxexport/decrypt.py` | 恢复覆盖状态及固定错误类别，排除密钥和数据库路径 |
| `collector/export_searchable.py` | 导出状态、结构不兼容和处理失败，不取消息文本 |
| `qkb-follow.py` 与受控检索入口 | 检查点、待嵌入状态与服务不可用类别 |
| `setup/schedule.py` | 可选诊断任务；不依赖 AI 整理任务成功才能运行 |
| 独立接收服务 | 持久化回执、安装认证、分组后台、保留期与撤销 |

接线必须保留现有返回码语义，不把“已执行未验收”转换成完成。旧部署副本仍需显式迁移，不能仅凭主仓库版本认定安装已经更新。

## 4. 测试与发布门槛

以下场景必须使用临时目录、合成回执与合成秘密样本完成；不需要真实微信和付费模型。

1. 默认仅本地：安装、诊断、生成诊断包不发网络请求；诊断状态目录不落在 vault 内。
2. 数据最小化：合成配置、错误与日志中插入聊天、联系人、密钥和路径，验证它们既不进入队列，也不进入上传包；未知字段服务端拒绝。
3. 版本和身份：安装编号稳定；不同安装分离；复制知识库不复制身份；实际入口为旧版时能够识别。
4. 主链路：配置损坏、依赖缺失、权限不足、磁盘不足、任务超时、半完成恢复、索引积压的状态可区分；诊断错误不影响主任务退出码。
5. 用户授权：未经同意不发送；关闭后停发；未发队列可处理；单次确认绑定报告指纹；重定向不泄漏提交凭据。
6. 接收闭环：通过真实回环 HTTP 连接完成登记、上传、持久化、回执查询和后台分组；模拟响应不能代替这一测试。公网 HTTPS 部署另行验收。
7. 故障与恢复：断网后持久化重试，重复投递不重复入库，队列溢出有记录，恢复事件正确归并，旧事件不会覆盖新状态。
8. 服务端边界：错误凭据、跨安装访问、撤销后继续上传、重放、过大请求、非法字段与 HTML 注入均有负向测试。
9. UI 与留存：后台未登录不可访问；休眠/断联显示未知而非机器损坏；清理策略可验证；通知不包含私密资料。
10. 发布：更新真实版本文件和变更日志；新旧测试通过；在新提交上核验 Git 标签；报告客户端与服务端是否已部署，不用创建标签冒充可用线上服务。
