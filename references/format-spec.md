# 格式与分类规范（★ 产出质量的标准）

> 本文件规定**每一页该怎么写**、**信息该怎么归类**、**什么算好什么算坏**。
> 配套：`templates/tpl-*.md`（骨架）· `examples/`（范例）· 根目录 `CLAUDE.md`（业务规则）。

---

## 一、通用规则（所有 wiki 页）

### 1.1 frontmatter 三件套（缺一不可）
```yaml
---
id: <uuid>           # 唯一；新建用新 uuid，别复制导致重复
context: <上下文名>   # 检索分组用；一般 = 页面主题
created: YYYY-MM-DD
tags: []
---
```
> ⚠️ 缺 `id`/`created` → **检索库不索引**（静默漏掉）。

### 1.2 四类标注（**区分事实与推断**）
每条信息必须落到四类之一：

| 标注 | 含义 | 写法 |
|---|---|---|
| `｜**事实**` | 聊天/附件里**明确存在** | 「8/28 天津首付 102000」｜**事实** |
| `｜**计划**` | 提到但**尚未发生** | 「9/2 带差额 2 万」｜**计划（未落实）** |
| `｜**意义（解读）**` | **AI 的推断** | 「训练重心或转向心态」｜**意义（解读）** |
| `｜**待确认**` | 证据不足 | 「老侯意向未知」｜**待确认** |

> ❌ **把解读写成事实**是最严重的违规——会让人把 AI 的猜测当真相。

### 1.3 内链
- 一律 `[[页面名]]`
- 引用证据层用**路径式**：`[[raw/chatlogs/<会话>/<YYYY-MM>|YYYY-MM]]`（可点回原话）
- 人名带别名：`[[<教练A>]]（帅哥/张<教练A>）`

## 二、五类页面的格式

### 2.1 `journal/YYYY-MM-DD.md` ——「我的每一天」（时间主轴）
```markdown
# 2026-09-10（周四）｜今日主线：<一句话概括今天最重要的 1-3 件事>

## 今日事件与意义

### <维度1：如 工作 / 项目名>
- **[[某人]]（别名）**：<事件> → [[项目]] · [[raw/chatlogs/.../2026-09|2026-09]]｜意义：…｜**事实**

### <维度2：如 家庭 / 爱好>

## 今日待办 / 碎片
- <未完成的事> → [[项目]]（**计划**）

## 今日图片 / 附件
![[<媒体文件名>]]
```
**要点**：按**人/项目维度**分组（不是按时间流水）；每条都要有「→链接」和「｜标注」。

### 2.2 `people/<姓名>.md` —— 人物（人物轴）
```markdown
> 关系：<一句话> ｜ 来源：<会话名> <条数>（<时间范围>）

## 背景
## 关键事实        ← 分小标题归拢（如「训练体系」「风格与金句」）
## 关联
- [[项目]] — <角色>
## 时间线（事件 + 意义）
- 2026-09-02 <事件> → [[2026-09-02]] · [[项目]]｜意义：…｜**事实**
## 记录目录
- [[raw/chatlogs/某人/2026-09|2026-09]]
```
**要点**：时间线**每人一行**、**必须链到当天 journal 与项目**；
**生活琐事不上人物页**（留在 journal）。

### 2.3 `projects/<项目>.md`
```markdown
> 所属：[[大类]] ｜ 状态：进行中 ｜ 最后更新：YYYY-MM-DD

## 一句话
## 背景 / 起因
## 当前进展      ← ★ 以**最近 3 个月**信息为准（见 §三 时效性）
## 下一步
## 相关人员      ← [[人]] 列表
## 素材          ← 链 raw/media/、raw/docs/
## 历史          ← 过时信息挪这里，不删
```

### 2.4 `monthly/YYYY-MM.md` / `quarterly/YYYY-QN.md` —— 汇总层（检索第一层）
```markdown
## 本月主线（1-3 条）
## 关键决定      ← 含金额/日期
## 未结事项
## 人物动向
## 项目进展
```
**要点**：每行**必须带下钻链接**（`[[YYYY-MM-DD]]`、`[[项目]]`、`[[人]]`）。

### 2.5 `tasks/<slug>.md` —— 搁置/待实践事项
```markdown
> 状态：待实践 / 搁置 / 已连接项目 ｜ 相关人员：[[人]] ｜ 项目：[[项目]]
## 是什么 / 为什么搁置 / 怎么重启
```

## 三、信息怎么归类（三层路由）

拿到一条新信息，按顺序判断：

```
① 能认出属于某个项目？   → 写进 projects/<项目>.md
② 认不出，但是点子/邀约/碎片？ → 写进 [[个人]] 或 [[商业]] 的「待收纳碎片」
③ 已识为一件事、但搁置了？   → 建 tasks/<slug>.md
```

**判断不了的** → 放「待收纳碎片」并标记，**不要硬塞进某个项目**。

### 大类层级（用户自定）
```
<大类A>  ← 公司/主业/爱好 等
   ├─ <项目1>
   │    └─ <子项目/前身>
   └─ <项目2>
<大类B>
<个人>
```
> 层级由用户在 setup 第 1 步给出（「你主要管哪几条线」）。

### 时效性优先级（**凌驾于其它来源**）
```
近 3 个月聊天/语音  >  群里的 PDF/PPT/图片  >  更早聊天  >  （仅作历史）旧库迁入
```
⚠️ **超过 3 个月且无后续更新的信息，不得写成「当前状态」** → 挪到「历史」小节。

### 人名处理
- 带别名：`[[正名]]（别名）`
- **跨会话推断同一人**（同一人可能被叫不同称呼：昵称/全名/简称）；拿不准就标「疑似同一人」
- **语音发言人未标注不臆测** → 写「（发言人未标注）」

## 四、什么算好 / 什么算坏

| ✅ 好 | ❌ 坏 |
|---|---|
| 「8/28 天津首付 **102000**（渤海银行面签）」｜**事实** | 「聊了买房的事」（没数字没结论） |
| 每条带 `→[[项目]]` `→[[当天]]` | 孤零零一句话，点不出去 |
| 解读明确标 `｜**意义（解读）**` | 把「他可能想合作」写成「他要合作」 |
| 过时信息挪到「历史」 | 把 3 个月前的进展当「当前进展」 |
| 按人/项目分组 | 按时间流水抄一遍 |
| 摘录要点 | 原样粘贴聊天记录 |

> **一句话**：整理层是**提炼**，不是**搬运**。原始记录在 `raw/chatlogs/`，整理页只留「有意义的部分 + 可点回去的链」。
