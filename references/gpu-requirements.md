# 本地模型的显卡要求（实测清单）

> 本文回答一个具体问题：**要把本系统用到的本地模型全跑起来，最低需要什么显卡？**
> 数据来自实际部署环境（模型大小实测）。

---

## 一、本系统实际用到的本地模型

| 模型 | 大小（实测） | 用途 | 必需？ |
|---|---|---|---|
| **`qwen3-embedding:4b`** | **2.5 GB** | 向量嵌入（检索的核心） | ✅ **必需** |
| **`bge-reranker-v2-m3`** | **~0.6 GB**（Q8_0 量化，0.57B 参数） | 检索重排（精排 Top-K） | ⭕ 可省（退回单阶段） |
| whisper `base` | 0.14 GB | 语音转写（默认） | ✅ 若接语音 |
| whisper `tiny` | 0.07 GB | 语音转写（最快） | ⭕ 替代 |
| whisper `medium` | 1.46 GB | 语音转写（较准） | ⭕ 可选 |
| whisper `large-v3-turbo` | 1.54 GB | 语音转写（最准） | ⭕ 可选升级 |
| `minicpm4.1` | 5.0 GB | 本地小 LLM（备用） | ⭕ 非必需 |

> **大 LLM / VLM 不在本地跑**（一律走 API），所以不计入下表。

---

## 二、实际显存占用（不是模型文件大小）

显存占用 = **权重** + **KV cache** + **计算缓冲**，通常比文件大 20–120%：

| 模型 | 文件大小 | **实际显存** | 说明 |
|---|---|---|---|
| 嵌入 `qwen3-embedding:4b` | 2.5 GB | **~3.5 GB** | 含 2K 上下文的 KV cache |
| 重排 `bge-reranker-v2-m3`（Q8_0） | ~0.6 GB | **~1.2 GB** | cross-encoder，短输入，占用小 |
| whisper `base` | 0.14 GB | **~0.6 GB** | 计算缓冲占大头 |
| whisper `large-v3-turbo` | 1.54 GB | **~2.5 GB** | |
| 本地 LLM `minicpm4.1` | 5.0 GB | **~6.5 GB** | 含较长上下文 KV |

---

## 三、按「组合」算最低门槛

| 场景 | 组合 | **实算显存** | 最低卡 |
|---|---|---|---|
| **① 最小可用** | 只跑嵌入 | 3.5 GB | **4 GB** |
| **② 全本地（小语音）** | 嵌入 3.5 + 重排 1.2 + whisper base 0.6 | **5.3 GB** | **6 GB** |
| **③ 全本地（大语音）** | 嵌入 3.5 + 重排 1.2 + whisper turbo 2.5 | **7.2 GB** | **8 GB** ✅ |
| **④ 再加本地 LLM** | ③ + 7B 量化 ~6.5 | ~13.7 GB | **16 GB** |

> ⭐ **8GB 门槛正好卡在「全套本地 + 高质量语音」这条线上**（7.2 GB，留一点余量）。
> 重排模型 Q8_0 只占 0.6 GB —— 比预想的小得多，所以 8GB 卡跑全套**很宽裕**。

> **串行加载**：Ollama 默认会按需换出模型（`OLLAMA_MAX_LOADED_MODELS`），
> 所以 6GB 卡也能跑全部——只是每次切换要重新加载（几秒~几十秒）。
> 想「同时常驻」就要按③算。

---

## 四、结论：最低门槛

| 你的目标 | **最低显卡** | 典型卡 |
|---|---|---|
| **只想要向量检索** | **4 GB** | GTX 1650 / MX570 / Apple M1(8G) |
| **要全本地（嵌入+重排+语音）** | **8 GB** ✅ **推荐门槛** | RTX 3060Ti / 4060 / **Apple M2 Pro(16G)** |
| **要舒服、有余量** | **12 GB** | RTX 3060 12G / 4070 |
| **还想本地跑个小 LLM** | **16 GB+** | RTX 4080 / 4090 / Apple M4 Pro(24G+) |

> **⭐ 硬规则（用户拍板）**：
> **本地模型的门槛是 8GB 显存**。
> - **≥ 8GB** → 可以本地跑（嵌入 + 重排 + 语音）
> - **< 8GB** → **一律走 API**，本地只跑纯脚本
>
> **大模型（LLM / VLM）永远走 API**，不要为它上显卡。

## 五、常见机器的实际判定

| 机器 | 可用显存 | 能本地跑什么 |
|---|---|---|
| Apple M1/M2 基础款（8–16G） | ~6–12 GB（统一内存 75%） | 嵌入 ✅ · 语音 ✅ · 重排 ⚠️ |
| **Apple M4（32G）** | **~24 GB** | **全部 ✅**（含本地小 LLM 也行） |
| Apple M4 Pro/Max（36–64G） | ~27–48 GB | 全部 ✅ 宽裕 |
| RTX 3060 12G | 12 GB | 全部 ✅ 舒适 |
| **RTX 4060 / 3060Ti（8G）** | 8 GB | **全部 ✅ 刚够**（推荐门槛） |
| RTX 4080 / 4090（16–24G） | 16–24 GB | 全部 ✅ 宽裕 + 本地 LLM |
| 无独显 / 集显 | <4 GB | ❌ **全部走 API**（本地只跑纯脚本） |

---

## 六、显存不够怎么办（三条路）

| 方案 | 做法 | 代价 |
|---|---|---|
| **换小模型** | 嵌入用 `qwen3-embedding:0.6b`、语音用 `tiny`、不部署重排 | 质量下降 |
| **串行加载** | 设 `OLLAMA_MAX_LOADED_MODELS=1`，按需换入换出 | 切换有延迟（几秒） |
| **借算力 / 走 API** | 重活放 GPU 机（Tailscale）或全走 API | 需要网络；API 有费用 |

> 详见 `performance-tiering.md`（分级决策）与 `models-as-api.md`（换 API）。
