# 性能分级与「增量 / 批量」分离

> **两条铁律**：
> ⭐ **硬门槛：8GB 显存**。低于 8GB → **一律走 API**（本地只跑纯脚本）。
> 上面 `xl`–`md` 才是「可本地跑」的档位；`sm` 及以下不建议本地推理。
> 💡 **具体到「本系统实际用到的模型要多少显存」**：见 （含实测模型清单与最低门槛：4GB 可用 / 8GB 全本地）。
> ① **增量处理**可以用「本地长时间运行的机器」——量小、随时跑、不赶时间
> ② **首次大批量处理**（回填历史）**必须**用 **API** 或 **高性能 GPU 服务器** ——
>   别用弱机器硬扛，几小时 vs 几天的差别
>
> **所以：setup 一开始就要判定机器性能**，据此决定「什么在本地跑、什么走 API」。

---

## 一、为什么必须分开

| | 增量（日常） | 批量（首次回填） |
|---|---|---|
| **数据量** | 每天几十~几百条消息 | 几万~几十万条 |
| **时间要求** | 不赶（4h 一轮） | 要一次跑完 |
| **弱机器表现** | ✅ 完全够用 | ❌ **几小时 → 几天** |
| **正确做法** | **本地跑**（省 API 费） | **API 或高性能 GPU** |

> **一句话**：日常用本地细水长流，回填时借算力一次冲过去。

---

## 二、性能分级（setup 会自动判定）

`setup/detect.sh` 会输出 `gpu_tier`，按显存分级：

| 分级 | 显存 | 典型卡 | **本地能跑** | **必须走 API** |
|---|---|---|---|---|
| **xl** | ≥20GB | 4090 / 5090 / A6000 | 嵌入 + 重排 + 语音 + **7B 量化 LLM** | 大 LLM / VLM |
| **lg** | ≥12GB | 4080 / 4070Ti | 嵌入 + 重排 + 语音 | 大 LLM / VLM |
| **md** | ≥8GB | 3070 / 4060 | 嵌入 + 重排 + 语音 | LLM / VLM |
| **sm** | ≥4GB | 3050 / T4 | ❌ **不够，一律走 API** | **全部** |
| **xs / cpu-mac** | <4GB 或无独显 | — | ❌ **不够，一律走 API** | **全部** |

> **Apple Silicon**：按**统一内存的 ~75%** 折算可用显存。
> M1/M2 基础款（8–16GB）≈ `sm` 级；M4 Pro/Max（24–64GB）≈ `md`–`lg` 级。

### 落到具体任务

| 任务 | 模型大小 | `xl` | `lg` | `md` | `sm` | 无独显 |
|---|---|---|---|---|---|---|
| **向量嵌入** | ~2.5GB | ✅ | ✅ | ✅ | ✅ | ⚠️ CPU 慢但可跑 |
| **Reranker 重排** | ~2.3GB | ✅ | ✅ | ⚠️ | ❌ | ❌ |
| **语音转写** (whisper) | 0.1–3GB | ✅ | ✅ | ✅ | ⚠️ | ⚠️ 慢 |
| **整理（LLM）** | 大 | ⚠️ 7B 勉强 | ❌ | ❌ | ❌ | ❌ |
| **看图（VLM）** | 大 | ❌ | ❌ | ❌ | ❌ | ❌ |

> ⚠️ **大 LLM 与 VLM 一律走 API** —— 本地跑量化小模型质量明显掉，且拖慢整机。
> 本系统的设计本来就假设「整理」这一步是可插拔的（见 `engine/`）。

## 三、推荐组合（按你的机器）

### 场景 A：高性能机器（有 4080+ 或 Apple Silicon 高配）
```
嵌入    → 本地 Ollama（GPU 加速）
重排    → 本地 llama-server --reranking
语音    → 本地 whisper
整理    → ★ 外部 API（DeepSeek 等）
看图    → ★ 外部 API
批量回填 → 本地 GPU 跑（嵌入/语音可本地，LLM 仍走 API）
```

### 场景 B：普通机器（无独显 / 集显）
```
嵌入    → ★ 外部 API（qkb provider=openai）
重排    → 不部署（退回单阶段检索）
语音    → ★ 外部 ASR API
整理    → ★ 外部 API
看图    → ★ 外部 API
批量回填 → ★ 全部走 API
```
> 本地只跑**纯脚本**（解密/转码/文件操作）——零成本、零门槛。

### 场景 C：借算力（推荐给普通用户）
把**重活**放到一台有 GPU 的机器上（哪怕是临时的），本机只做调度：
```
本机   → 脚本 + 调度 + Obsidian
GPU 机 → 嵌入 / 重排 / 语音（经 Tailscale 或 SSH 隧道）
API    → 大 LLM / VLM
```
见 `vector-search.md` 的「GPU 高可用」架构。

## 四、大模型必须走 API（首推 DeepSeek）

「整理」和「看图」这两步用的是**大 LLM / VLM**，本地跑不动（质量+速度都不行）。
**推荐用外部 API**：

| 用途 | 推荐 | 说明 |
|---|---|---|
| **整理（LLM）** | **DeepSeek V4.1 Flash** | 中文强、**有峰谷价**（空闲时段半价）、便宜 |
| 看图（VLM） | 按需选用 | 看打勾表/日程表/截图 |

> 💡 **选 DeepSeek 的理由**：
> - **中文语料强**（本系统的内容几乎全中文）
> - **峰谷定价**：把定时任务排在空闲时段（工作日 9–12/14–18 之外）**价格减半**
> - 便宜 → 适合「每天跑一两次」的整理任务
>
> 配置方式见 `models-as-api.md`（**统一走 OpenAI 兼容协议**，换厂商只改 `base_url`）。
> 成本估算见 `cost.md`。

## 五、setup 里怎么用这份文档

**第 0 步**跑 `detect.sh` → 得到 `gpu_tier`

**第 2 步**（配 API）**据此决策**：

| gpu_tier | 该怎么问用户 |
|---|---|
| `xl` / `lg` | 「你的机器不错，嵌入/重排/语音可以**本地跑**，省钱；大模型（整理/看图）建议用 API。要这样配吗？」 |
| `md` / `sm` | 「嵌入可以本地，但**重排和整理建议走 API**（本地太慢）。」 |
| 无独显 | 「建议**全部走 API**——本地只跑脚本。这样不挑机器、也不用装模型。」 |

**首次回填前必须提醒**：
> ⚠️ 「接下来要处理过去 N 个月的**全部**历史数据，这是**一次性大批量任务**。
> 用你这台机器本地跑可能要**几小时到几天**；建议用 **API** 或**借一台 GPU 机器**跑完再回来。」
