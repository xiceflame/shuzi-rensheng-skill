# 常驻服务清单（后台守护）

> 本系统除了**定时任务**，还有几个**常驻服务**。它们不「到点跑一次」，而是**一直守着**。
> 缺了不是报错，而是「某些能力静默失效」——所以容易被忽略。

## 一、服务一览

| 服务 | 类型 | 作用 | 缺了会怎样 |
|---|---|---|---|
| **嵌入代理** `embed-proxy` | launchd 常驻 | 嵌入高可用：GPU 在线走 GPU，离线回落本机 | GPU 一关机，嵌入就卡住 |
| **索引跟随** `qkb-follow` | launchd 常驻 | 内容变了自动重建索引 | 新内容搜不到，要手动 ingest |
| **算力健康** `compute-health` | launchd 定时 | 探活 GPU 主机，更新健康状态 | 问题靠人工发现 |
| **同步监听** `syncthing-watch` | launchd 常驻 | 监听同步完成 → 触发下游 + 通知 | 整理任务不自动触发 |
| **冲突哨兵** `conflict-sentinel` | cron 每 10 分钟 | 收口 Syncthing 冲突副本（保留最新，旧的归档） | 冲突文件堆积，可能读错版本 |
| **采集刷新** `wxexport.refresh` | launchd 每 4h | 解密导出微信数据 | 数据不更新 |
| **全量导出** `wxexport.full` | launchd 每周 | 全量历史导出 | 历史查询数据停在过去 |
| **OpenClaw gateway** | launchd 常驻 | agent 运行时（若用 OpenClaw） | agent 全停 |

## 二、为什么「常驻」和「定时」要分开

- **常驻**：需要**秒级/持续响应**的（监听同步、代理请求、跟随变更）
- **定时**：**到点跑一次**就行的（导出、转写、汇总）

> ⚠️ 常见错误：把「索引跟随」做成定时（每 10 分钟跑一次），
> 结果是**新内容有 10 分钟延迟**；做成常驻则近乎实时。

## 三、怎么部署（macOS）

`setup/schedule-macos.sh` 生成的是**定时**任务。
常驻服务用 launchd 的 `KeepAlive`：

```xml
<key>KeepAlive</key><true/>
<key>RunAtLoad</key><true/>
```

Linux 用 `systemd`；Windows 用「计划任务」的「触发器：登录时」+「重复间隔」。

## 四、不装这些行不行

| 想要的效果 | 最少需要 |
|---|---|
| 只是能用 | **不需要任何常驻服务**（手动跑 ingest / 手动触发整理） |
| 自动化 | 采集刷新 + 索引跟随 |
| 多机高可用 | 嵌入代理 + 算力健康 |
| 实时 | 同步监听 + 冲突哨兵 |

> **渐进式**：先跑通「手动」，再逐步加常驻服务。别一开始全上。
