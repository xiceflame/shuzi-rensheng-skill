# 微信采集：版本升级应对与参考来源

> **定位**：微信版本升级后采集失效时，看这里「怎么解决、去哪找方案」。
> 完整的参考仓库与社区帖列表见附录 `sources.md`。

---

## 一、核心认知：升级影响的是「方法」，不是「数据」

| 层 | 升级后 | 对系统的影响 |
|---|---|---|
| **已解密落盘的数据**（`raw/`） | 永远有效（已是普通文件） | ✅ 零影响 |
| 已拿到的密钥 + 加密库快照 | 对那批文件仍有效 | ⭕ 保留快照可随时重导 |
| **密钥提取方法**（脚本/工具） | 每个版本可能失效 | ⚠️ **唯一要修的东西** |

> **系统不会报废**：升级只暂停「新一轮采集」，已入库的历史、整理、检索照常运转。
> 方法恢复后从断点续采，新消息自动补齐（微信本地库有完整历史）。

---

## 二、应对流程

### 首选：别急着升级
采集端**锁定当前可用的微信版本，关闭自动更新**（采集机是专用机器时尤其应该）。
每次想升级前，先确认新版本的密钥方案已有人适配。

### 已升级 / 被迫升级后
```
1. 跑现有采集 → 「密钥 0 个」= 方法失效
2. 查新方案 → 附录 sources.md 的「出了问题去哪找」（看雪搜索
   「微信 <版本号> 数据库密钥」是第一站，安全社区通常率先发逆向分析）
3. 按新原理适配脚本（验证逻辑——HMAC 验真、解密参数——通常不用改，
   变的是内存搜索特征/对象偏移）
4. 断点续采 → 数据自动补齐
```

### 历史经验（本机实测过的适配点）
| 微信版本 | 变化 | 我们改了什么 |
|---|---|---|
| 4.0 | 数据库改 SQLCipher 4、多分片 | 解密参数对齐（reserve=80 等） |
| 4.0.3.36+（Win）/ 4.0.3.80+（Mac） | 内存中密钥存放方式变化 | 从「明文搜索」改为「Config.Cipher 掩码解混淆」 |
| 4.1.x | 新建 `xwechat_files` 目录、迁移旧库 | 数据路径探测（已自动化） |

## 三、架构保障：采集层可插拔

大脑侧（整理/检索/知识库）**只认 `~/wechat-export/` 目录结构，不认采集工具**。
所以：换工具、换平台、甚至手工导入，摆对位置即可；采集方式的变化不波及系统其余部分。

## 四、合规边界（给客户部署时才需要展开）

- **自用**（自己的号、本机处理、不分发）：风险低，实践中无从检测
- **帮朋友配**：中等
- **打包成产品分发**：高风险——公开解密工具 2025-10 起已被微信官方函告下架（PyWxDump、
  chatlog 等），商业化分发正是被打击的对象
- **结论**：知识库部分（整理/检索/图谱）可放心产品化；**微信采集环节按个案交付**，
  并让客户书面确认知情（用于备份本人数据）。不接微信的手工导入路径完全合规。
